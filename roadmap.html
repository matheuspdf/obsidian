01 Help Desk Conceitual
🎯 1.1 — Conceitos fundamentais teoria ›
O que saber
  • Queue management: como organizar e priorizar a fila de chamados
  • SLA: o que é, como funciona, o que acontece se for violado
  • Time management: gerir múltiplos chamados simultâneos sem deixar nenhum cair
Como praticar
  • Simule chamados reais do dia a dia na Turim: documente problema, passos e resolução
  • Crie um "diário de chamados" pessoal no Obsidian — com o tempo vira sua própria KB
  • Estude os SLAs que a Turim já usa (pergunte ao gestor se existem formais)
📝 1.2 — Documentação de chamados escrita técnica ›
O que saber
  • Descrever o problema de forma clara, factual e sem ambiguidade
  • Registrar todos os passos de troubleshooting realizados
  • Anotar o resultado de cada passo — inclusive os que não funcionaram
  • Escrever pensando em quem vai ler depois, sem contexto anterior
Como praticar
  • Documente o próximo chamado que você atender usando o modelo: Problema → Passos → Resultado → Solução final
  • Revise a documentação depois e pergunte: alguém sem contexto entenderia isso?
🔍 1.3 — Processo de troubleshooting metodologia ›
Os 7 passos
  • 1. Definir o problema com precisão
  • 2. Coletar informações detalhadas (usuário, máquina, logs)
  • 3. Identificar a causa provável
  • 4. Elaborar um plano de resolução
  • 5. Implementar as mudanças
  • 6. Verificar se o problema foi resolvido
  • 7. Documentar tudo — inclusive se o problema voltou
02 Hardware Prático
Contexto Turim: frota principal é Dell OptiPlex 7020 Micro e Latitude series. Priorize o aprendizado com esses modelos.

🖥️ 2.2 — Ferramentas de diagnóstico do dispositivo lab ›
Ferramentas Windows
  • msinfo32 — hostname, CPU, RAM, OS, versão de BIOS
  • Task Manager — processos, CPU/RAM em tempo real, terminar processos travados
  • Event Viewer — logs de erro, Warning, Critical
  • ipconfig /all — IPv4, IPv6, MAC, DHCP, DNS
  • WinDBG — análise de dump de BSOD (stop codes)
Lab prático
  • Rode msinfo32 e ipconfig /all em uma máquina da Turim e documente tudo
  • Abra o Event Viewer e filtre por erros dos últimos 7 dias — identifique o que é relevante
  • Simule um processo travado no Task Manager e mate-o
  • Analise um arquivo .dmp de BSOD com WinDBG (pode baixar um exemplo online)
🔌 2.3 — Portas e cabos identificação ›
Vídeo & display
  • HDMI — digital, áudio+vídeo, mais comum
  • DisplayPort — maior largura de banda, monitores profissionais
  • USB-C / Thunderbolt 3/4 — vídeo + dados + carga em um cabo
  • DVI — digital, sem áudio, legado
  • VGA — analógico, legacy, ainda aparece em projetores
USB
  • USB-A — conector padrão retangular
  • USB-B — impressoras e hubs
  • USB-C — reversível, Thunderbolt-compatível
  • Micro USB — dispositivos móveis antigos
Rede
  • RJ-45 — conector Ethernet padrão
  • UTP — cabo sem blindagem, uso geral
  • STP — blindado, ambientes com interferência
Energia
  • Desktop — cabo IEC C13 (3 pinos)
  • Notebook — fonte proprietária ou USB-C PD
  • Converters — necessários para conectar portas incompatíveis (ex: HDMI→VGA)
↗ Conexão: roadmap.sh → Network Fundamentals → Physical Layer
🔧 2.4 — Componentes internos e instalação prático ›
Componentes
  • RAM: DDR4/DDR5 — slots, compatibilidade, dual-channel
  • Armazenamento: SATA HDD/SSD → mais lento; NVMe M.2 → mais rápido
  • GPU: slot PCIe x16; verificar requisito de fonte
  • Placa Wi-Fi/Bluetooth: slot PCIe x1 ou M.2 Key E
  • Motherboard: socket define compatibilidade de CPU
Device Manager
  • Verificar dispositivos com ! amarelo (problema de driver)
  • Atualizar driver: automático via Windows Update ou manual pelo site do fabricante
  • Reverter driver quando uma atualização quebra algo
  • Desativar/reativar dispositivo para "reiniciar" o driver
  • Firmware: sempre verificar release notes antes de atualizar — risco de brick
⚠️ 2.5 — Troubleshooting de hardware diagnóstico ›
Checklist básico
  • Cabo de energia conectado e tomada funcionando?
  • Botão de liga/desliga pressionado por tempo suficiente?
  • LEDs de status acesos?
  • Monitor no input correto?
  • Requisitos do app compatíveis com o hardware? (CPU arch, RAM, GPU, disco)
Dell específico (Turim)
  • LED branco piscando: POST OK, aguardando boot
  • LED laranja piscando: falha de hardware — contar os pulsos para identificar o código de erro
  • Consultar Dell Error Code no site da Dell com o número de pulsos
  • BSOD stop codes → WinDBG ou pesquisar o código (ex: 0x0000003B)
03 Redes & Acesso Fundamentos + Lab
Este bloco tem a maior sobreposição com o roadmap.sh/network-engineer. Os tópicos de DNS, DHCP, IP, comandos de rede e periféricos correspondem diretamente à fase de fundamentos do roadmap.

👤 3.1 — Acesso a recursos de rede AD · Entra ID ›
Active Directory & Entra ID
  • Criar, editar e desativar usuários no AD e Entra ID
  • Grupos de segurança vs grupos de distribuição
  • Verificar membros de grupo para resolver problema de acesso
  • RBAC — verificar permissões atribuídas a um usuário
  • Resetar senha no AD / Entra ID
  • MFA: apps autenticadores (Microsoft Authenticator), SMS, chave FIDO
↗ roadmap.sh → Security → Authentication & Authorization
Drives e políticas
  • Mapear drive SMB: \\servidor\pasta via Explorador ou net use
  • OneDrive: sincronização, backup de pastas conhecidas
  • gpupdate /force — forçar política de grupo imediatamente
  • Verificar GPO aplicada com gpresult /h gpo.html
🖨️ 3.2 — Periféricos e conectividade suporte ›
Impressoras
  • Verificar conectividade (USB ou rede — fazer ping no IP da impressora)
  • Carregar papel corretamente (guias de papel ajustadas)
  • Desentupir papel: abrir tampas indicadas, puxar com cuidado sem rasgar
  • Limpar fila de impressão travada: parar serviço Spooler, limpar C:\Windows\System32\spool\PRINTERS, reiniciar serviço
  • Trocar toner: verificar modelo correto, remover lacre antes de instalar
Outros periféricos
  • Headphones/Microfone: verificar dispositivo padrão no painel de som, drivers, mute físico
  • Drives externos: verificar no Gerenciador de Discos se aparece sem letra
  • Webcam: permissões de app no Windows, drivers, testar no app Câmera
  • Teclado/mouse: wired vs wireless — receptor USB, pilhas, pareamento Bluetooth
  • Webex Desk Pro: verificar rede, conta Webex, atualização de firmware
🌐 3.3 — Conectividade de rede comandosroadmap.sh ›
Conceitos
  • DNS: resolve nome → IP. Testar com nslookup
  • DHCP: distribui IPs automaticamente. APIPA = 169.254.x.x = sem DHCP
  • Gateway padrão: roteador da rede local — necessário para sair da subnet
  • IP privado: 10.x, 172.16-31.x, 192.168.x. IP público: o resto
  • WLAN SSID: nome da rede Wi-Fi. Verificar se está no SSID correto
  • Firewall: pode bloquear portas — verificar regras quando há falha de acesso
↗ roadmap.sh → Networking Fundamentals → TCP/IP, DNS, DHCP, Subnetting
Comandos essenciais
  • ipconfig /all — IP, máscara, gateway, DNS, MAC
  • ping <IP> — testa alcançabilidade
  • tracert <host> — rastreia o caminho até o destino
  • nslookup <domínio> — resolve DNS manualmente
  • netstat -an — conexões ativas e portas abertas
  • ping6 / traceroute6 — equivalentes para IPv6
  • ipconfig /release + /renew — renovar IP via DHCP
  • ipconfig /flushdns — limpar cache DNS local
04 Sistema Operacional & Apps Windows + Mobile + Cloud
🪟 4.1 — Problemas de Windows lab ›
Display & sistema
  • Configurar resolução, escala e múltiplos monitores
  • BitLocker: o que é, como pegar a recovery key (Entra ID / MBAM), situações de bloqueio
  • Windows Update: verificar, instalar, pausar, resolver falha de update
  • Limpar cache do browser (Ctrl+Shift+Del) — resolve muitos problemas de acesso a sistemas web
  • Task Manager: terminar processo travado (kill process)
Boot & recuperação
  • Sequência de boot: BIOS/UEFI → Bootloader → Windows
  • Modo seguro: F8 ou msconfig → Boot → Safe Boot
  • Gerenciamento de energia: planos de energia, hibernação vs sleep
  • Acessibilidade: Narrador, Lupa, Alto Contraste, Teclado na Tela
  • OneDrive: backup de Documentos/Desktop/Imagens, restaurar versão anterior
📱 4.3 — Dispositivos móveis MDM ›
Suporte básico
  • Reiniciar dispositivo (força tarefa vs reinício limpo)
  • Configurar e-mail corporativo (Exchange/M365) em iOS e Android
  • Instalar app de colaboração (Teams, Webex) e fazer login corporativo
  • Resolver problemas de conectividade: Wi-Fi, VPN no celular
MDM básico (Microsoft Intune)
  • O que é MDM: gerenciamento remoto de dispositivos móveis corporativos
  • Enrolar dispositivo no Intune (iOS e Android)
  • Políticas de conformidade: PIN obrigatório, criptografia ativa
  • Wipe remoto: apagar dispositivo perdido ou roubado
☁️ 4.4 — Virtualização e Cloud (Azure) AZ-104roadmap.sh ›
Conceitos
  • Hipervisor: software que cria e gerencia VMs (Hyper-V, VMware, VirtualBox)
  • Tipo 1: roda direto no hardware (Hyper-V Server, ESXi)
  • Tipo 2: roda sobre um SO (VirtualBox, VMware Workstation)
  • IaaS / PaaS / SaaS: camadas do modelo de nuvem
  • Azure: provedor cloud da Microsoft — usado na Turim via Entra ID
↗ roadmap.sh → Cloud Networking → Azure Fundamentals
Praticar
  • Criar conta Azure gratuita (portal.azure.com)
  • Subir uma VM Windows simples e conectar via RDP
  • Ver como o Entra ID do Azure se conecta ao AD local (hybrid join)
  • Este tópico é coberto em profundidade pelo AZ-104
📦 4.5 — Problemas de aplicativos suporte ›
Instalação
  • Apps aprovados: Microsoft Store, portal corporativo do Intune
  • Fontes não confiáveis: riscos de malware, política da empresa
  • Requisitos de compatibilidade: arquitetura x64/ARM, versão do SO
Apps comuns
  • Outlook/Teams/M365: configurar conta, resolver login, limpar cache de perfil
  • Cisco Webex: instalação, configurar áudio/câmera, testar reunião
  • OneDrive: sincronização, conflitos de arquivo, compartilhamento
05 Segurança Crítico
Como técnico de help desk, você é um alvo frequente de engenharia social. Conhecer esses ataques não é opcional — é parte do trabalho.

🎣 5.1 — Ameaças e investigação básica segurançaroadmap.sh ›
Tipos de ameaça
  • Phishing: e-mail falso que tenta roubar credenciais ou instalar malware
  • Malware: vírus, ransomware, spyware — software malicioso
  • Spam: e-mails indesejados em massa, às vezes com payload
  • Spoofing: falsificar remetente de e-mail ou IP de origem
  • Acesso não autorizado: tentativa de login em conta alheia
↗ roadmap.sh → Security → Threats & Vulnerabilities
Como agir
  • Rodar scan de malware: Windows Defender (integrado) ou Malwarebytes
  • Isolar máquina suspeita da rede antes de escanear
  • Reportar tentativas de phishing para a equipe de segurança
  • Senhas fortes: 12+ caracteres, maiúscula, número, símbolo, sem reutilização
  • MFA: reduz drasticamente o risco mesmo com senha comprometida
🎭 5.2 — Engenharia social alerta ›
Cenários comuns no help desk
  • "Sou o diretor e preciso que você resete minha senha agora, urgente"
  • "Estou em viagem e perdi o acesso, me adiciona no grupo de segurança"
  • "Sou da TI central e preciso de acesso remoto à sua máquina"
  • E-mail com link urgente pedindo validação de conta
Como se proteger
  • Sempre verificar identidade antes de resetar senha ou dar acesso
  • Ligar de volta para o ramal oficial — nunca para o número que a pessoa forneceu
  • Urgência e pressão são sinais de alerta, não de confiança
  • Escalate se tiver dúvida — é melhor pedir confirmação do que ser responsável por um incidente
🔒 5.3 — Dados e conformidade PII · LGPD ›
  • PII (Dados Pessoais): CPF, e-mail, telefone, endereço — protegidos pela LGPD
  • Dados confidenciais: informações financeiras de clientes da Turim — tratar com máximo cuidado
  • Dados proprietários: código, estratégias internas — não compartilhar fora da empresa
  • Nunca enviar dados sensíveis por canais não autorizados (WhatsApp pessoal, e-mail pessoal)
  • Incidente com dados: reportar imediatamente ao gestor e equipe de segurança
06 Ferramentas & Windows Server Lab completo
Este bloco é o que mais se beneficia do lab de VMs. Suba um Windows Server 2022 (eval gratuito, 180 dias) no VirtualBox e pratique cada item aqui.

🖥️ 6.1 — Acesso remoto prático ›
Ferramentas
  • RDP (mstsc.exe): acesso remoto nativo do Windows — padrão corporativo
  • Remote Assistance: usuário convida o técnico — bom para suporte sem VPN
  • Cisco Webex: videoconferência + compartilhamento de tela para suporte
  • TeamViewer: acesso remoto sem precisar de VPN, cross-platform
  • VNC: open-source, multiplataforma — menor controle de segurança
  • Action1 RMM: acesso remoto + execução de scripts nos endpoints da Turim
Lab prático
  • No lab de VMs: ative RDP no servidor e no cliente, conecte do host físico via mstsc
  • Instale TeamViewer Free em uma VM e faça suporte remoto a partir do host
  • Simule um chamado completo: usuário reporta problema → você acessa remotamente → resolve → documenta
🔎 6.2 — Ferramentas de pesquisa e documentação metodologia ›
Como pesquisar bem
  • IA (Claude, Copilot): ótimo para explicar erros e sugerir soluções — sempre valide antes de aplicar em produção
  • Buscas técnicas: use o erro exato entre aspas: "stop code 0x0000003B"
  • Fóruns: Spiceworks, Reddit r/sysadmin, Microsoft Q&A
  • Docs oficiais: Microsoft Learn, Dell Support, Cisco Docs
  • KB interna: registre soluções de chamados recorrentes para reutilizar
IA: limitações importantes
  • Pode alucinar — nunca aplique um script gerado por IA em produção sem testar
  • IA generativa cria conteúdo; IA preditiva classifica/prevê — são coisas diferentes
  • Dados sensíveis da Turim não devem ser colados em ferramentas de IA externas
  • Use para aprender e rascunhar — não para substituir o julgamento técnico
🗄️ 6.3 — Windows Server e ferramentas administrativas labroadmap.sh ›
Serviços do Windows Server
  • AD DS: gerenciar usuários, grupos, OUs, domínio, GPOs
  • DNS: resolver nomes internos e externos, zonas forward/reverse
  • DHCP: escopos, reservas de IP, leases, autorizar no AD
  • File Server: compartilhamentos SMB, permissões NTFS vs Share
  • Print Server: adicionar impressoras, compartilhar, gerenciar fila via Print Management
↗ roadmap.sh → Networking Services → DNS, DHCP, File Sharing
Lab: passo a passo resumido
  • VM Server (DC01): WS2022 Eval, IP fixo 192.168.56.10
  • Instalar AD DS → promover a DC (domínio: lab.local)
  • Instalar DNS e DHCP → criar escopo 192.168.56.50–100
  • Criar File Server: pasta compartilhada para Domain Users
  • Criar Print Server: impressora virtual compartilhada
  • VM Cliente (WIN10): ingressar no domínio, mapear drive via GPO
  • Testar tudo: gpupdate /force, RDP entre VMs, acesso ao compartilhamento
