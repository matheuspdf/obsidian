Segundo plano

Para que um dispositivo se comunique com outro dispositivo, o endereço MAC do destino deve ser conhecido. Com o IPv6, um processo chamado Descoberta de Vizinhos (Neighbor Discovery) usando o protocolo NDP ou ND é responsável por determinar o endereço MAC de destino. Você coletará informações de PDU no modo de simulação para entender melhor o processo. Não há pontuação no Packet Tracer para esta atividade.

Instruções

Parte 1: Descoberta de vizinhos IPv6 Rede local

Nesta parte, você obterá o endereço MAC de um dispositivo de destino na mesma rede.

Etapa 1: Verifique se há vizinhos que ele descobriu no roteador.

a.     Clique no RTA Router. Selecione a guia CLI e emita o comando show ipv6 neighbors do modo EXEC privilegiado. Se houver entradas exibidas, remova-as usando o comando clear ipv6 neighbors.

b.     Clique em PCA1, selecione a guia Área de Trabalho e clique no ícone Prompt Command.

Etapa 2: Alterne para o Modo de Simulação para capturar eventos.

a.     Clique no botão Simulação no canto inferior direito da janela Topologia do Packet Tracer.

b.     Clique no botão Mostrar Tudo/Nenhumno Painel de Simulação até que Filtros da Lista de Eventos – Eventos Visíveisexiba Nenhum.

c.     Clique em Edit Filters. Selecione a guia IPv6 na parte superior e marque as caixas para ICMPv6 e NDP . Feche a janela Editar Filtros ACL. Agora os Filtros da Lista de Eventos exibem ICMPv6 e NDP.

d.     No prompt de comando em PCA1, execute o comando ping —n 1 2001:db8:acad:1: :b. Isso iniciará o processo de ping PCA2.

e.     Clique em Reproduzir (Hands Free) em PLAY CONTROLS fora do Painel de simulação. Se solicitado, clique em View Previous Eventsna janela Buffer Full - Packet Tracer. Você deve ter aproximadamente 12 entradas na janela.

Pergunta:

Por que as PDUs ND estão presentes?

Área de Resposta

Para enviar pacotes de ping ICMPv6 para o PCA2, o PCA1 precisa saber o endereço MAC do destino. O IPv6 ND solicita essas informações na rede.

f.      Clique no quadrado na coluna Tipo para o primeiro evento, que deve ser ICMPv6.

Pergunta:

Uma vez que a mensagem começa com este evento, existe apenas uma PDU de saída. Na guia Modelo OSI, qual é o Tipo de Mensagem listado para ICMPv6?

Área de Resposta

Tipo de mensagem de eco ICMPv6:128

Observe que não há endereçamento de Camada 2. Clique no botão Próxima Camada >> para obter uma explicação sobre o processo ND (Descoberta de Vizinhos).

g.     Clique no quadrado ao lado do próximo evento no Painel de simulação. Deve estar no dispositivo PCA1 e o tipo deve ser NDP.

Perguntas:

O que mudou no endereçamento da Camada 3?

Área de Resposta

O endereço de destino agora é um endereço multicast IPv6 de FF02: :1:FF00:B

Quais endereços da Camada 2 são mostrados?

Área de Resposta

O endereço de origem é PCA1 MAC — 0001.427E.E8ED e o endereço MAC de destino é 3333.FF00.000B

Quando um host não sabe o endereço MAC do destino, um endereço MAC de multicast especial é usado pelo IPv6 Neighbor Discovery como o endereço de destino da Camada 2.

h.     Volte para a lista de eventos. Selecione o primeiro evento NDP no SwitchA.

Área de Resposta

Não. O switch não altera as informações da Camada 2, ele apenas encaminha o quadro.

Área de Resposta

Parte 2: Descoberta de vizinhos IPv6 Rede remota

Na Parte 2 desta atividade, você executará etapas semelhantes às da parte anterior, exceto que, neste caso, o host de destino está em outra LAN. Observe como o processo de descoberta de vizinhos difere do processo observado na parte anterior. Preste muita atenção a algumas das etapas de endereçamento adicionais que ocorrem quando um dispositivo se comunica com um dispositivo que está em uma rede diferente.

Etapa 1: Capturar eventos para comunicação remota.

a.     Clique no botão Reset Simulation para limpar os eventos anteriores. Exiba e limpe todas as entradas na tabela de dispositivos vizinhos IPv6 como foi feito na parte anterior.

b.     Verifique se apenas ICMPv6e NDP estão listados em Event List Filters - Visible Events.

c.     No prompt de comando no PCA1, emita o comando ping –n 1 2001:db8:acad:2::a para pingar o host PCB1.

d.     Clique em Reproduzir (Hands Free) em PLAY CONTROLS fora do Painel de simulação. Se solicitado, clique em Exibir eventos anteriores na janela Buffer cheio -- Packet Tracer.

e.     Quando o processo de ping estiver concluído, clique no quadrado na Coluna Tipo para o primeiro evento, que deve ser ICMPv6. Como a mensagem começa com este evento, existe apenas uma PDU de saída. Observe que está faltando as informações da Camada 2 como fazia no cenário anterior.

f.      Clique no primeiro evento NDP no dispositivo PCA1 .

Pergunta:

Qual endereço está sendo usado para o IP Src na PDU de entrada?

Área de Resposta

O endereço local do link para PCA1 — fe80::201:42ff:fe7e:e8ed

O IPv6 Neighbor Discovery determinará o próximo destino para encaminhar a mensagem ICMPv6.

g.     Clique no segundo evento ICMPv6 para PCA1. O PCA1 agora tem informações suficientes para criar uma solicitação de eco ICMPv6.

Pergunta:

Qual endereço MAC está sendo usado para o MAC de destino?

Área de Resposta

0001.961d.6301, o endereço MAC de G0/0/0 de RTA

h.     Clique no próximo evento ICMPv6 no dispositivo RTA. Observe que a PDU de saída do RTA não possui o endereço de destino da camada 2, isso significa que o RTA mais uma vez precisa realizar uma descoberta de vizinho para a interface que possui a rede 2001:db8:acad:2:: porque não conhece os endereços MAC dos dispositivos na LAN G0/0/1.

i.      Ir para o primeiro evento ICMPv6 para o dispositivo PCB1.

Pergunta:

O que está faltando nas informações de saída da Camada 2?

Área de Resposta

O endereço MAC de destino deve ser determinado para o endereço de destino IPv6.

j.      Os próximos eventos NDP estão associando os endereços IPv6 restantes a endereços MAC. Os eventos NDP anteriores associados endereços MAC com endereços de Link Local.

k.     Pule para o último conjunto de eventos ICMPv6 e observe que todos os endereços foram aprendidos. As informações necessárias agora são conhecidas, então PCB1 pode enviar mensagens de resposta de eco para PCA1.

l.      Clique em Reset Simulation (Redefinir Simulação) no Simulation Panel (Painel de Simulação). No prompt de comando do PCA1 repita o comando para ping PCB1.

m.   Clique em Reproduzir (Hands Free) para concluir o processo de ping. Clique em Exibir eventos anteriores se solicitado na janela Buffer cheio.

Pergunta:

Houve algum evento do NDP?

Área de Resposta

Não.

n.     Clique no único evento PCB1 na nova lista.

Perguntas:

A que corresponde o endereço MAC de destino?

Área de Resposta

A interface do roteador G0/0/1 no RTA

Por que o PCB1 está usando o endereço MAC da interface do roteador para fazer suas PDUs ICMP?

Área de Resposta

Como o dispositivo de destino está em outra rede, o PCB1 aborda a PDU para o MAC de interface de gateway padrão. O RTA determinará como endereçar a PDU na Camada 2 para enviá-la para seu destino.

a.     Volte ao modo de Realtime.

b.     Clique em RTA e selecione a guia CLI. No prompt do roteador, digite o comando show ipv6 neighbors.

Área de Resposta

PCA1 e PCB1

Área de Resposta

Há entradas para o PCA2?

Área de Resposta

Perguntas para reflexão

1.     Quando um dispositivo requer o processo IPv6 Neighbor Discovery?

Área de Resposta

Quando o endereço MAC de destino não é conhecido. Esse processo é semelhante ao ARP com IPv4.

2.     Como um roteador ajuda a minimizar a quantidade de tráfego IPv6 Neighbor Discovery em uma rede?

Área de Resposta

O roteador mantém tabelas vizinhas para que não precise iniciar o ND para cada host de destino.

3.     Como o IPv6 minimiza o impacto do processo ND nos hosts de rede?

Área de Resposta

Ele usa um endereço multicast para que apenas um punhado de endereços estaria escutando as mensagens de descoberta de vizinhos. O IPv6 cria um endereço MAC de destino multicast especialmente criado que inclui uma parte do endereço do nó.

4.     Qual a diferença entre o processo de descoberta de vizinhos quando um host de destino está na mesma LAN e quando está em uma LAN remota?

Área de Resposta

Quando um host de destino está no mesmo segmento de LAN, apenas o dispositivo que corresponde ao endereço IPv6 responde e outros dispositivos soltam o pacote. Quando o dispositivo é remoto, o dispositivo gateway (geralmente um roteador) fornece o endereço MAC da interface na interface local para o MAC de destino e, em seguida, procura o endereço MAC na rede remota. Em seguida, o roteador colocará o par de endereços IPv6/MAC respondente na tabela Vizinhança IPv6. Semelhante a uma mesa ARP no IPv4.
